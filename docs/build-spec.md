# Kinbir for iPhone: Build Spec

Working name: **Kinbir** (ቅንብር). Bundle ID: `com.geni.kinbir`.

This is the complete brief for the Kinbir iPhone app. It is written so the app can be built
without asking the owner anything. Read all of it before changing code.

---

## 0. The owner's situation

- The owner (Geni) is a content creator, not a developer. Windows PC only, no Mac.
- Every build happens on GitHub Actions macOS runners. Never tell her to open Xcode.
- Test device: iPhone 13 Pro Max.
- Build 1 is installed with **SideStore** from the `.ipa` that CI attaches to each run.
- Nobody can run the app on a real phone from here. Never claim something works on device.
  After each build, give her a short plain-English test checklist.
- Text written for her: short, simple, bullet points, no em dashes.

---

## 1. What the app is

Kinbir turns text into a natural **Amharic voiceover** in the user's own cloned voice.

1. The user writes or pastes Amharic, **or** pastes English text or an article link and Kinbir
   writes the Amharic script.
2. The user taps one button and gets an Amharic voiceover.
3. The user plays it, saves it or shares it.

The app is a thin client. All AI work happens on the existing Kinbir server at
`https://api.kinbir.com`. The app never holds an AI key.

### In scope

| Area | Build 1 |
|------|---------|
| Hear the Kinbir voice before signing in (short demo) | Yes |
| Sign in with email and a 6-digit code (sign up is the same step) | Yes |
| Clone your own voice from a 10 to 40 second video | Yes |
| Write or paste Amharic | Yes |
| English text or article link in, Amharic script out | Yes |
| Make the voiceover, with progress | Yes |
| Play, share and save the audio | Yes |
| Library of recent voiceovers (the server keeps them 48 hours) | Yes |
| Choose, rename and delete voices | Yes |
| Credit balance | Yes, read only |
| Delete account | Yes |

### Change of plan, 2026-11-13

The owner decided the app should have everything the website has, added one part at a
time. Build 2 adds footage, music and the finished video (section 5.10). Build 3 adds the
avatar. Build 4 adds the voice extras: fix a word, speech input, script options and English
voiceovers. Rule 1 below (Amharic output only) holds until Build 4.

### Never in the app

- Stripe checkout and the billing portal (Apple requires its own purchases, see section 9).
- All admin and internal tools.

### Build 2 (needs a server update, see section 9)

- Buying credits with Apple in-app purchase.
- A ready-made built-in voice, so a new user can make a full voiceover in the first minute
  without cloning. Cloning becomes the upgrade.

## 2. Rules that must not be broken

1. Amharic output only. Every `/generate` and `/rewrite` call uses the server default
   language (`am`); the app never sends `language: "en"`.
2. Light appearance only, matching the Kinbir landing page.
3. Only the five brand colours in section 4. No gradients. No soft shadows.
4. The access code is the only credential. It lives in the Keychain, never in
   `UserDefaults`, never in a URL, never in a log line.
5. Never show a raw status code to the user. Show the server's sentence when it has one.
6. Build 1 has no buying and no link that leads to buying outside the app.
7. No third-party runtime dependencies. Swift, SwiftUI, AVFoundation, Security only.
8. The app collects nothing itself. No analytics SDK, no tracking calls.

## 3. Technology

- Swift 5.9, SwiftUI, iOS 17.0+, iPhone only, portrait only.
- The Xcode project is generated by **XcodeGen** from `project.yml`. Never commit `.xcodeproj`.

## 4. Design

The website's landing page design language, made simpler for a phone.

### Colours (the only ones allowed)

| Token | Hex | Use |
|-------|-----|-----|
| lime | `#B9FF66` | accent fill behind black text, the main call to action, markers |
| black | `#191A23` | text, borders, hard shadows, secondary buttons |
| grey | `#F3F3F3` | secondary card fill, input fill |
| white | `#FFFFFF` | page ground |
| muted | `#5A5B66` | secondary text on white |

Lime is never used as text colour. Errors use black text on a grey card with a black border,
with the word "Problem" in the title; there is no red in the palette.

### Components

- **Card:** white or grey or lime fill, 1 pt black border, corner radius 24, and a hard offset
  shadow: a solid black shape of the same radius drawn 5 pt lower. No blur.
- **Primary button:** lime fill, black text, 1 pt black border, radius 14, hard 4 pt shadow,
  minimum height 52. One primary button per screen.
- **Secondary button:** black fill, white text, radius 14, minimum height 52.
- **Quiet button:** plain black text, underlined.
- **Marker:** a word in a heading with a lime rounded rectangle (radius 7) behind it.
- **Field:** grey fill, 1 pt black border, radius 14.

### Layout rules

- 20 pt side margins. 16 pt between cards.
- Headings are medium weight, never bold.
- Every screen states one thing to do. Extra options go below it or in the Account tab.
- Every tappable control is at least 44 pt tall.
- All screens scroll, so nothing is cut off with large text sizes.

## 5. Screens

Navigation after sign-in is a three-tab bar: **Create**, **Library**, **Account**.

### 5.1 Welcome (signed out)

- Logo mark and the name Kinbir with ቅንብር.
- Heading: "Amharic voiceovers in your own voice" with "your own voice" on a lime marker.
- **Hear it card:** a text field prefilled with a short Amharic sentence and a "Play" button.
  Calls `POST /demo/generate`, polls `GET /demo/{id}` every 2 seconds until `done`, downloads
  `GET /demo/{id}/audio` and plays it. Shows "Preparing the voice. The first time can take a
  minute." while waiting. Limit 120 characters in the field.
- Primary button: "Start free". Opens Sign in.
- Footer links: Privacy, Terms (open `https://kinbir.com/privacy` and `/terms` in Safari).

### 5.2 Sign in

Two steps on one screen.

1. Email field, button "Send me a code". Calls `POST /auth/request-code`.
2. Six-digit code field (number pad, one-time-code autofill), button "Continue".
   Calls `POST /auth/verify`. Stores `access_code` in the Keychain, then loads `GET /whoami`.

- "Use a different email" returns to step 1.
- "Send a new code" is available after 30 seconds.
- Server sentences are shown as they are ("that code is not right - 4 tries left").

### 5.3 Create tab

The home of the app.

- Top row: "Kinbir" on the left, the credit balance as a pill on the right.
- **No voice yet:** a lime card "Clone your voice first" with the button "Clone my voice"
  that opens Enroll. The script box stays usable so a script can be prepared.
- **Script card:** a large text editor, placeholder "Write Amharic, or paste English or a link."
  A line under it describes what the app sees: "Amharic script", "English text" or "Link".
  A "Paste" button and a "Clear" button.
- **Action button** changes with the content:
  - Empty: disabled "Make voiceover".
  - Link: "Get the article". Calls `POST /extract`, puts the article text in the editor.
  - English: "Write Amharic script". Shows the estimated cost from `POST /rewrite/estimate`
    under the button, then calls `POST /rewrite` with `stream: true` and fills the editor as
    the text arrives. The English source is kept so "Undo" can bring it back.
  - Amharic: "Make voiceover". Calls `POST /generate`, then opens Generating.
- Voice line under the button: "Voice: NAME" with "Change" that opens Voices.
- Trial note when `trial_max_chars` is set: "Free credits voice up to N Amharic characters at
  a time." with a live count.
- The draft text is saved on the device per account, so leaving the app does not lose it.

### 5.4 Generating

- Polls `GET /jobs/{id}` every 3 seconds.
- Shows: "In line" (queued), "Recording your voiceover" (running) with part X of Y when
  `segments_total` is known, and a note that the first one of a session takes longer.
- `done` opens Result. `failed` shows the server's error and a "Back to my script" button.
- Leaving the screen does not cancel the job. It appears in the Library when ready.

### 5.5 Result

- Player card: play or pause, a scrub bar, elapsed and total time.
  Audio comes from `GET /jobs/{id}/playback` (small mp3), saved to a temporary file.
- Primary button "Share or save": downloads `GET /jobs/{id}/audio` (wav) and opens the iOS
  share sheet, which includes Save to Files.
- The script text, selectable, with a "Copy" button.
- Line: "Kept for 48 hours. Save it if you need it later."
- "Make another" returns to Create with an empty editor.

### 5.6 Library tab

- `GET /jobs`. Rows newest first: first words of the script, length in seconds, time made,
  status. Only voice jobs are shown (`type` absent or `generate`).
- Tap a finished row to open Result. Tap a running row to open Generating.
- Pull to refresh. Empty state: "Your voiceovers appear here for 48 hours."

### 5.7 Voices (from Create or Account)

- `GET /voices`. Each row: name (or "Voice 1"), "In use" tag on the active one.
- Tap a row to make it active (`POST /voices/activate`).
- Row menu: Rename (`POST /voices/rename`), Delete (`DELETE /voices/{id}`) with confirmation.
- Only Amharic voices are listed (`ref_language` absent or `am`).
- Button "Add a voice" opens Enroll. Hidden when five voices exist.

### 5.8 Enroll (clone my voice)

1. Consent line, shown above the script: "I am recording my own voice and face. I give
   permission for an AI voice of me to be created and used only by me."
2. The script to read, from `GET /enroll/script` (`personal`).
3. Tips: quiet room, phone close, read naturally, 10 to 40 seconds.
4. Two buttons: "Record now" (front camera, 40 second limit) and "Choose a video".
5. After a video is chosen, the app checks duration (10 to 40 seconds) and size (under 60 MB)
   on the device, then uploads to `POST /enroll` with `access_code` and `language=am`.
6. Result:
   - `approved`: "Your voice is ready." and the free credits granted, then back to Create.
   - `pending`: "Thanks. You will get an email when it is approved."
   - Any `advice` lines from the server are listed.

### 5.10 Make a video (Build 2)

Opened from a finished voiceover with "Make a video".

1. **Setup.** Shape (Vertical 9:16 or Horizontal 16:9). Footage: Stock, Stock + mine, or
   Only mine. With either "mine" choice the user adds clips first. The plan price comes
   from `POST /broll/estimate`.
2. **Plan.** `POST /broll/plan`, then `GET /jobs/{id}` every 3 seconds. The plan job id is
   saved on the phone the moment it is returned, because planning is paid for and must
   never be submitted twice.
3. **Fill the shots.** Stock: `POST /broll/search` in slices until `remaining` is 0. Own
   clips: `POST /broll/match`. Then `GET /broll/plan/{id}` for the full list.
4. **Stock limit.** The server answers 200 with `retry_after`, or with nothing searched and
   work remaining. The app waits once and tries again. If it is refused twice it shows
   "Stock footage is not available right now" and asks the user to upload their own footage
   for the empty shots. New clips are placed on the empty shots at once.
5. **Shots.** Each shot shows its clip and the words it covers. Tapping a shot opens a
   sheet: pick another clip (`/broll/choose`), search with other words (`/broll/search`
   with `beat` and `query`), or use one of the user's clips (`/broll/use-upload`).
6. **Own clips.** Up to 10 videos or photos at a time, sent to `POST /uploads/chunk` in
   16 MB parts, in order, tagged with the voiceover's `job_id`.
7. **Finish.** Music (`GET /music`, with a listen button) and a captions switch. "Make
   video" is disabled until every shot has footage. `POST /assemble` at 1080p costs 2
   credits and is charged once.
8. **Video.** `GET /assemble/{id}` every 3 seconds, with Stop (credits returned). When
   done: an in-app player on the 720p copy, and "Save or share video" which downloads
   `video.mp4`. Videos are kept 48 hours and listed in the Library (`GET /videos`).

Not in Build 2: split, merge and reorder shots, logo, on-screen graphics, uploading your own
music, 4K and 8K.

### 5.9 Account tab

- Email, credit balance, plan name when there is one.
- Build 1 line under the balance: "Buying credits inside the app arrives in the next build."
- Rows: My voices, Privacy, Terms, Support (mailto support@kinbir.com), Sign out.
- "Sign out" signs out at once. It is harmless: signing back in takes one code.
- "Delete my account": explains it is permanent, asks for the email typed back, then calls
  `POST /account/delete`. On success the Keychain is cleared and the app returns to Welcome.
- App version and build number at the bottom.

## 6. Server contract

Base URL `https://api.kinbir.com`. JSON in and out unless noted.

- GET and DELETE requests carry the header `X-Access-Code`.
- POST requests carry `access_code` in the JSON body.
- Errors come back as `{"detail": "sentence"}` or `{"detail": {"message": "sentence"}}`.

| Call | Purpose | Notes |
|------|---------|-------|
| `POST /auth/request-code` `{email}` | email a code | 429 when too many sends |
| `POST /auth/verify` `{email, code}` | sign in or sign up | returns `access_code`, `is_new`, `has_voice`, `credits_balance` |
| `GET /whoami` | account, voices, balance | `trial_max_chars` is null once paid |
| `GET /voices` | voice list | |
| `POST /voices/activate` `{voice_id}` | choose voice | |
| `POST /voices/rename` `{voice_id, name}` | rename | |
| `DELETE /voices/{id}` | delete | |
| `GET /enroll/script` | text to read | public |
| `POST /enroll` multipart `video, access_code, language=am` | clone voice | mp4 or mov, 10 to 40 s, 60 MB |
| `POST /extract` `{url, owns_content: true}` | article text from a link | |
| `POST /rewrite/estimate` `{text}` | credits for a script | |
| `POST /rewrite` `{text, stream: true}` | Amharic script | server-sent events: `delta`, `done`, `error`; may answer plain JSON |
| `POST /generate` `{text, draft_id?}` | start a voiceover | 402 when credits are short, 400 when no voice |
| `GET /jobs` | recent jobs | |
| `GET /jobs/{id}` | job status | `queued`, `running`, `done`, `failed` |
| `GET /jobs/{id}/playback` | mp3 for the player | may be wav as a fallback |
| `GET /jobs/{id}/audio` | wav to save or share | |
| `POST /demo/generate` `{text}` | demo in the built-in voice | no account needed |
| `GET /demo/{id}`, `GET /demo/{id}/audio` | demo status and audio | |
| `POST /account/delete` `{confirm_email}` | delete account | |

### Error wording in the app

| Case | What the user reads |
|------|---------------------|
| 401 outside `/auth/` | "Your session is not valid any more. Sign in again." and the app signs out |
| 402 | the server sentence, plus "Buying credits inside the app arrives in the next build." |
| 5xx with no useful sentence | "Something went wrong on our side. Try again in a moment." |
| no connection | "No connection. Check your internet and try again." |
| anything else | the server sentence |

Every response model treats unknown or missing fields as optional, so a server change never
crashes the app.

## 7. State and storage

- `AppState` (one observable object): signed-in flag, `WhoAmI`, loading and error state.
- Keychain item `com.geni.kinbir.access_code`: the access code.
- `UserDefaults`: the draft script, keyed by a hash of the access code. Nothing else.
- Temporary directory: downloaded audio. Cleared when the app starts.

## 8. Testing

### 8.1 Unit tests (`Tests/`)

Pure logic, no network: request building, decoding of real response shapes, the event-stream
parser, error mapping, text kind detection (Amharic, English, link), formatters, multipart
bodies, the enroll duration and size rules.

### 8.2 End-to-end UI tests (`UITests/`)

The app has a built-in mock server (`MockAPI`) that is switched on by the launch argument
`-uiTestMock`. It is never used otherwise. The tests drive the real screens through the
whole product on the simulator:

1. Welcome appears, the demo plays to "ready".
2. Sign in with email and code.
3. An account with no voice sees "Clone your voice first", enrolls with the sample video
   path, and returns with a voice and free credits.
4. English text becomes an Amharic script.
5. A voiceover is generated, the result screen appears, the player is present.
6. The Library lists it.
7. Voices: the list opens and shows the voice in use.
8. Account: email and balance shown, delete stays locked until the email is typed, sign out returns to Welcome.
9. Error paths: a wrong sign-in code, and out of credits when writing a script.

Mock scenarios are chosen by further launch arguments: `-mockNoVoice`, `-mockNoCredits`.
The camera does not exist on the simulator, so in mock mode the Enroll screen offers
"Use sample video" in place of the camera.

### 8.3 Live contract check (`scripts/live_smoke.py`)

A small script CI runs against the real server. It only calls free public endpoints
(`/health`, `/enroll/script`) and checks the shapes the app depends on. It never signs in and
never spends credits. It is a separate CI job that does not block the build.

### 8.4 What only the owner can test

Real sign-in email, real camera recording, real voice cloning, real audio quality, the share
sheet. See `docs/test-checklist.md`.

## 9. Build 2: server changes (written, not deployed)

`docs/build-2-server-changes.md` holds the design for the server work. The server code is
not written yet. It lives in the Kinbir repo and the owner deploys it from her PC with
`scripts/deploy-api.ps1`:

1. **Apple purchases.** `POST /billing/apple` receives a signed StoreKit 2 transaction,
   verifies it with Apple, and grants credits once per transaction id. Consumable products
   mirror the website top-up. Subscriptions mirror Starter, Pro and Studio.
2. **Built-in voice.** Accounts with no voice of their own may generate in the built-in
   Kinbir voice (the owner agreed on 2026-11-12). A small free allowance on first sign-in
   replaces the grant that today arrives only after enrollment.
3. **Smaller free taste for app sign-ups**, so free users cost cents, not a dollar.

## 10. CI

`.github/workflows/ci.yml`, on every push:

1. XcodeGen, then an unsigned Release archive packaged as `Kinbir.ipa` (artifact, 30 days).
2. Unit tests on the simulator.
3. End-to-end UI tests on the simulator.
4. Live contract check (separate job, never blocks).

`.github/workflows/testflight.yml` is manual and needs the paid-account secrets. It is ready
for when the owner moves from SideStore to TestFlight.
